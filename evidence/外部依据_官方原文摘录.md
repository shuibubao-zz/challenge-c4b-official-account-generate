## 三、一个必须说清楚的边界：接口文档 ≠ 编辑器行为

出处 ①②③ 全部来自**服务端接口文档**，证明的是"通过 API 提交图文时平台会怎么处理"。
而文章讲的是"在公众号编辑器里 Ctrl+V 粘贴 HTML 会怎样"——**这两件事不是同一个机制**：

- 接口文档能证明的：JS 被去除、外部图片 url 被过滤、图片格式/大小限制。**→ 坑 4、坑 5 有官方依据。**
- 接口文档**证明不了**的：`class` 属性被剥离、`<h1>` 被降级、`<div>` 渲染不稳、`<pre>` 被压成一行。
  微信**没有公开过编辑器的 HTML 白名单文档**，我检索过开发者文档全站，没有找到。

所以下面这四条，本文的处理是：**不伪造出处，改为给出可复现的实测方式 + 明确标注"未找到官方出处"**。

| 坑 | 结论 | 依据类型 | 读者如何自己验证 |
|----|------|----------|------------------|
| 坑 1 `<style>`/`class` 失效 | 未找到官方出处 | L3 实测 + L4 旁证 | 粘贴一段带 class 的 HTML 到编辑器，保存后查看源代码 |
| 坑 2 `<h1>` 被征用 | 未找到官方出处 | L3 实测 | 正文里写 `<h1>`，保存后看是否被降级 |
| 坑 3 `<div>` 不靠谱 | 未找到官方出处 | L3 实测 | 用 `<div>` 做高亮框，预览正常、保存后盒子散架 |
| 坑 6 `<pre>` 被压成一行 | 未找到官方出处 | L3 实测（标记为【实测】） | 粘贴 `<pre>` 代码块，看缩进是否消失 |
| 坑 7 MathJax 失效 | **由坑 4 推出** | ✅ 官方明文（出处 ① "去除JS"） | MathJax/KaTeX 本质是 script，被去除即失效 |

坑 7 是个例外：它不需要单独找依据，因为 MathJax/KaTeX 的实现载体就是 `<script>`，
而"去除 JS"有官方明文。这是**从官方条文推出的结论**，不是实测猜测——本文在正文里也这样写。
