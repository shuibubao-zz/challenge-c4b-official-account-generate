## 文章内容的深度体现在哪

`卢怡然_C4B_文章源文件.md`（6660 字 + 3 张配图）不是清单式罗列，每个坑都写成三层：

1. **现象** —— 在编辑器里看到的是什么（"样式像被抽走""图片隔天裂开"）
2. **原因** —— 平台为什么会这样（`<h1>` 被标题字段征用、SVG 无法被重新上传）
3. **解法** —— 给出可直接抄的 HTML 对照（❌ 会丢的写法 vs ✅ 能活的写法）

v2 加固后，文章多出三层"只有做了查证才有"的内容：

- **依据级别标注**：每条坑都标明"官方明文 / 由官方推出 / 未找到官方出处"（配图 fig2 一图总览）
- **官方原文引用**：坑 4、坑 5 直接引用接口文档原文（"此处会去除JS""外部图片url将被过滤"）
- **一节专门的"这些规则哪些有官方依据"**：含依据分布图（fig3），并公开交代
  **查证过程抓出了我自己写错的一条规则**（"单篇不超过 100 张"查无出处，已删除）

文章另外有两处不是"转载可得"的内容：

- **"三段式盒子"**：没有 `<div>` 时如何用三个 `<p>` 拼出完整的高亮卡片（带真实代码）
- **可复核的实测数据**：双引擎字节一致、20 项 eval、与 starter 的量化对照，全部在 `evidence/` 里

以及一条明确观点：**真正的解法不是记住 7 条规则，而是把规则固化成会让机器报错的检查器**。

## 验证：怎么确认它真的能用

```bash
python wechat-publisher/scripts/selftest.py
# → 自检结果：20/20 通过   （满依赖环境，即装了 markdown/bs4/matplotlib/python-docx）
```

**自检口径（写实，两个数字都有真复现）：**

| 环境 | 结果 | 说明 |
|------|------|------|
| 满依赖（四个第三方库都装了） | **20/20** | 留档 `evidence/selftest_20项.txt`（含解释器路径） |
| 干净机器（一个都没装） | **18/20** | 留档 `evidence/selftest_18项_零依赖.txt` |

干净环境掉的两项是「双引擎结构等价（markdown 库 ↔ 零依赖）」和「数学公式：双引擎输出字节一致」
——它们**拿 markdown 库当参照物**，没有参照物就不可执行，不等于零依赖路径有 bug。
零依赖主路径本身在干净机器上完整可用（其余 18 项全过）。
对照组实验脚本：`evidence/selftest_双环境口径.py`（同一解释器跑两遍，唯一变量 = 依赖是否可见）。

20 项覆盖：主题系统、中文排版、零依赖解析、**双引擎结构等价**、
4 主题输出合规、h1 降级、callout、目录、元数据与页脚、图片 base64、
图片异常告警、纯文本输出、批量转换、docx 缺依赖提示、检查器能抓坏 HTML、代码块缩进、
**数学公式渲染/降级、公式双引擎字节一致、代码区 `$` 不误伤、`--math off` 开关**。

关键实测（留档在 `evidence/`）：

| 实测 | 结果 |
|------|------|
| 与 starter 同一输入对比 | 定制版多出元数据/摘要/页脚；无 h1/div/class/id |
| 两条解析引擎路径 | 输出 **sha256 完全一致** `1e506b85cffe6993…` |
| 真实文章转换 | 6660 字 / 15 个 h2 / 4 张图（3 配图 + 1 公式）/ 2 个表格，合规自检通过 |
| 官方依据核验 | 10 条官方原文片段全部联网核验"仍在页面上"（`外部依据_核验.py` 全绿） |
| 解包副本独立运行 | selftest 20/20，转换结果与源目录一致 |
| 公式渲染 | matplotlib mathtext → 200 DPI PNG → base64 内嵌，白底防深色模式隐形 |

## 诚实标注（没做的部分）

1. **没有真实发布到公众号** —— 无账号，也没有伪造链接或截图。
   已做的是**网页版发布**：https://wechat-article-layout-38529.app.workbuddy.host/（真实可访问，
   v2 加固后已同步为 6660 字带图版）。公众号后台发布按 `卢怡然_C4B_文章链接.md` 的 SOP
   由本人执行，后台阅读数据依然没有。
2. **没有接公众号官方 API 自动发布** —— 需要认证服务号 + IP 白名单，个人订阅号拿不到。
3. **坑 1、2、3、6 没有官方出处** —— 微信从未公开编辑器 HTML 白名单文档。这几条是实测 +
   同类工具旁证，文章与 `references/wechat_restrictions.md` 都如实标注，没有伪装成官方条文。
4. **官方文档存在内部矛盾**（字数上限、图片大小、格式清单三处），本文按更严格的口径执行，
   逐条裁定见 `evidence/外部依据_官方原文摘录.md` 第四节。
5. **`.docx` 只处理了文本、标题、粗斜体和表格文本**，未处理合并单元格与内嵌图片。
6. **公式用 mathtext 而非完整 LaTeX** —— 常见行内/行间公式够用，但不支持完整 LaTeX 宏包；
   公式渲染为图片后不可复制、不可搜索（这是公众号平台的约束，不是本工具的选择）。
7. **v1 曾写错一条规则** —— "单篇图片不超过 100 张"查无官方出处，v2 已删除并在文章里公开交代，
   `外部依据_核验.py` 里有防回归护栏。

## 依赖

- `.md` 输入：**零依赖**即可（有 `markdown` + `beautifulsoup4` 时优先用库）
